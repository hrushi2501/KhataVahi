# Google Play readiness — 11 November 2026

This is a source/artifact audit, not Google approval. No Play Console submission has occurred. The app is private/single-owner; public distribution adds console and policy obligations even when the software works locally.

## Verified in this version

- compileSdk/targetSdk 36, minSdk 26. Google currently requires API36 for new ordinary phone apps/updates after 31 August 2026: [target API policy](https://support.google.com/googleplay/android-developer/answer/11926878).
- Native Kotlin/XML, no ads or analytics SDK, no advertising identifier permission, no unnecessary runtime permission prompts.
- Final requested permissions: INTERNET, ACCESS_NETWORK_STATE, WAKE_LOCK, RECEIVE_BOOT_COMPLETED, plus AndroidX's app-specific signature receiver permission. The latter is internal broadcast protection; normal wake/boot permissions support WorkManager. No camera/location/contacts/SMS/storage/call/notification/battery-exemption permission. Removed unused foreground-service permission/service and diagnostics receiver.
- No background-persistence tricks, device-admin, accessibility service, overlay, install-package permission or battery-whitelist request. Android force-stop is respected; jobs resume after reopening, not while force-stopped.
- Cleartext traffic disabled; HTTPS app API and TLS-required Mac SQL connection; no database password/privileged API key shipped in APK/source control.
- Debug/unit/lint checks and minified release APK/AAB generation succeed. R8/resource shrinking enabled. Release artifacts are unsigned.
- Debug and release APK zip alignment check passes with 16KB page option. Packaged DataStore native libraries have PT_LOAD alignment16384 across all packaged ABIs. This is static artifact evidence, not a 16KB device qualification. [Android requirement](https://android-developers.googleblog.com/2025/05/prepare-play-apps-for-devices-with-16kb-page-size.html).
- Separate English/Gujarati resources, persistent language/theme selection, static loading skeletons, meaningful local-save feedback, guarded form submissions and audited soft deletion.

## Not yet attained / release blockers

1. **Production identity and signing.** Configure protected upload/signing keystore, secure key backup and Play App Signing; sign the AAB. Current APK/AAB is unsigned and cannot be treated as a distribution build. Decide the permanent applicationId before the first Play release. [Signing](https://developer.android.com/studio/publish/app-signing).
2. **Public privacy policy and Data safety.** Publish an accessible policy and link it inside the app and store listing. Describe Supabase, account email, customer names/phones/villages, financial entries, deleted history, logs, retention, security, sharing/export and deletion handling. Complete accurate SDK-inclusive Data safety declarations; no analytics does not mean no cloud collection. No reviewed public policy URL or submitted declaration exists. [User data](https://support.google.com/googleplay/android-developer/answer/10144311), [Data safety](https://support.google.com/googleplay/android-developer/answer/10787469).
3. **Owner-account/data-erasure process.** Ledger soft deletes deliberately retain financial history; they are not account erasure. If account creation is offered, provide the required in-app account-deletion request and web pathway with actual data erasure/clearly disclosed permitted retention. Resolve public signup/provisioning policy and remove unused signup capability or implement the complete compliant account lifecycle. No erasure/request portal is implemented. [Account deletion](https://support.google.com/googleplay/android-developer/answer/13327111).
4. **Play Console setup and review material.** Developer verification, package registration where applicable, support/contact details, listing text/icon/screenshots/feature graphic, category, content rating, target audience, ads declaration and protected reviewer App access instructions remain unsubmitted. Provide isolated reviewer data/account access, not the real owner's financial ledger or credentials. [Console requirements](https://support.google.com/googleplay/android-developer/answer/10788890).
5. **Financial features declaration.** Complete the form truthfully for bookkeeping. The app records amounts, not banking/loans/transfers; do not invent regulated-product claims. The declaration is not submitted. [Financial declaration](https://support.google.com/googleplay/android-developer/answer/13849271).
6. **Testing/production access.** Play pre-launch report, device/ANR/crash validation, API26/low-RAM/small-screen/large-font/accessibility coverage and signed-release runtime behavior remain incomplete. For applicable new personal developer accounts, closed testing requires at least12 testers continuously opted in for14days before applying for production access; account eligibility is unknown here. [Testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465).
7. **Recovery and security qualification.** Full fresh-install cloud restoration, logout/relogin with a populated ledger, long-offline token refresh, multi-device conflicts and complete release/session-storage security review still need end-to-end testing. Independent encrypted backup/restore is planned, not implemented. Cache-directory wipe/force-stop smoke test passes; native API37 cache-clear command stalled, and OEM behavior is not certified. Release artifacts need final 16KB/device testing.
8. **Final operational review.** Existing lint warnings remain (zero errors); exposed development credentials must be rotated; verify signup settings, backup availability and documented retention. No Play approval or production-readiness claim is made.

No console declarations have been filled with guesses, no real credentials are in public artifacts, and no app/account has been published by this task.
